# One More Bonk — minimal rebuild

独立重建版：借鉴已研究的 ForgeTax 核心闭环，复用已核验的规则与原创表现资产，重写最小局流程。

## 当前状态

这是新仓库的启动基线，尚不是可玩的完整游戏。原项目继续独立保留。

- `main`：已确认规则、范围与开发约束。
- `rebuild/minimal-core`：锤击内核、规则数据和自包含回归测试的首个工作分支。
- UI、剑素材、Session、存档和两个广告业务接点尚待分阶段接入。

## 已确认规则

- 原概率/价值/遗物结果链、有限供剑、主订单、金币与剑信用、原解锁闭环。
- 遗物上限8格，初始2格；第3–8格逐个广告解锁，同一玩家存档跨局永久保留，最多6次成功槽位奖励。
- 龙鳞广告每契约最多成功领取1次，进入原库存，由玩家提前手动使用；与永久槽位独立记账。
- 不带入旧XP、天赋、副单信用、预约和多重碎后恢复体系。

详见 [范围](Docs/SCOPE.md)、[架构](Docs/ARCHITECTURE.md)、[执行顺序](Docs/MILESTONES.md)。

## 开发基线

- Unity `6000.3.17f1`，URP `17.3.0`；先沿用已知版本。
- `rebuild/minimal-core`分支以仓库根目录作为新的Unity项目壳；尚无完整入口场景或可安装游戏包。
- 在工作分支运行 `sh Tools/verify-core.sh`，重跑自包含的133组概率向量。脚本需要本机Unity附带的Mono/C#编译器与Newtonsoft依赖，详见测试说明；不启动Unity编辑器，不读取旧项目。
- Google广告SDK尚未接入这个新壳，生产广告与奖励业务单独验证。

## 来源与验证边界

规则来自现有独立C#实现、公开研究模型和已确认补丁差异；不是原Steam源码或完整二进制等价声明。概率向量检查只覆盖给定状态的抽签输出，不能替代完整遗物生命周期、实际获取、广告、真机与整局平衡验证。

本仓库只迁入明确白名单。Unity缓存、旧版本构建、个人视频、本机绝对路径和签名凭据不进入Git。
