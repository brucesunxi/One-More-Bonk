# 资产复用白名单

保留已确认明亮工坊风格、原创新剑表现和12阶规划。重建不要求重画既有素材，也不代表所有规划系列已完成。

[来源清单](asset-source-manifest.json)只描述候选白名单和来源身份，不是导入回执。`repo_path: null`表示本清单尚未登记仓内副本；不把旧工程路径改写成虚假的新仓文件链接。

## 按需要迁入

- 工坊背景、铁砧、十孔控台、按钮、面板、道具图集和通用碎裂图；布局JSON只在新页面确实使用时迁入。
- 中文字体连同原许可、来源记录和meta；不能只依赖开发机已安装字体。
- 已完成普通剑/商人剑几何及材质、shader依赖。生成器需要审阅依赖并适配只读外观描述，不能把旧UI控制器一起搬入。
- 规则数据由核心实施分支负责，仍以单一目录为准；旧`v08-design.json`不作为新壳运行配置自动带入。

`RiskWorkshop`各partial、旧场景、旧Session/Career、旧Build、旧测试fixture不属于直接迁入白名单。图标/缩略图若藏在旧partial，只提取独立显示部分并重新绑定。

## 迁入规则

1. 按来源相对路径和SHA256核对固定快照，不实时链接旧Assets。
2. 资源带同名`.meta`及必要依赖闭包，保留GUID和导入设置；新场景/脚本用明确新身份。同一工程不导入两份相同GUID。
3. 核对中文字体、alpha/9-slice、材质/shader和外观裁切；发现缺依赖时逐项补，不以整拷旧项目解决。
4. 实际迁入后更新清单的`repo_path`、导入状态和必要适配说明。候选shader引用材质需要复核，不能默认照搬旧实验室引用。

不带Library/Temp/Logs、旧构建/研究归档、录屏及帧图、用户个人图片、未选生成稿、本机路径、生成会话metadata或签名凭据。项目许可不自动覆盖字体/第三方依赖，保留其原许可。

Unity的GUID与导入设置保存在meta；缺失meta会生成新身份并破坏引用。参见[官方元数据说明](https://docs.unity3d.com/Manual/AssetMetadata.html)。
