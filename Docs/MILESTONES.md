# 最小实施顺序

`main`先放已确认文档与约束；后续`rebuild/minimal-core`交付核心与自包含测试。分支、提交和合并由仓库负责人控制，不把规划当已完成。

| 阶段 | 最小产物 | 继续门槛 |
| --- | --- | --- |
| 1. 独立核心 | 白名单规则、必要模型/目录及`Tools`测试 | 独立编译；133概率向量和相关保护/效果顺序检查通过；shim不进入Assets |
| 2. 五页灰盒 | 最小Session、独立存档，锻造/订单/剑柜/遗物/商人 | 赠礼→锤击/入神→收手→交单→商店/替换→商人→失败重开或21单/延期→续玩可走通；原解锁有效 |
| 3. 两广告 | 永久2→8槽、每契约ward×1 | 分别earned一次提交；重复/交叉/过期回调、取消/无填充、写失败重试与重启权益连续性通过 |
| 4. 皮肤与候选 | 复用现风格及已完成剑，唯一Android候选包 | 五页/锁态/替换清楚，输入和后台返回正确，独立安装/保存不碰旧包旧档；同包验证可追溯 |

阶段2可先用8槽全开内部对照定位移植错误，随后必须启用玩家初始2槽。阶段3验证2槽玩家不看广告也可购买并替换；不以内部满配代表玩家。分别记录2/4/8槽和龙鳞有无的实际供给、构筑及失败原因，不继承旧版本胜率。

阶段4套回已有皮肤，不等待20页、全部规划剑系列或成长系统。测试广告配置、真实SDK获奖与生产配置分别报告；fixture跳关不能当自然通关证据。

核心与数据变更运行`Tools`中的golden检查和相关有序效果测试；Session/领奖变更验证资源守恒、一次提交和持久化。尚无可运行入口时不编造命令或完成状态。

如果核心仍需整套Career/旧页面才能编译，先修移植边界；若重复发奖、存档交叉写或规则偏移，先修正确性。灰盒未闭环前不扩页面、不加广告点、不铺新框架。按实际产物决定下一步，不承诺无依据工期。
